## Part 1: the bug fixes (adopt both)

1. **Fix L, the layout-mixed calibration pool.** I am adopting it as a bug fix. Each window calibrates (feature standardisation and AdaBN) only on earlier windows of its own antenna layout, with the same thresholds. A home has one layout, so this is the honest deployment figure, even though the screen puts it about 3 points lower.
2. **Fix F, the cadence fallback.** Screen it first; it takes about 5 minutes with `ils_extract`. When no channel's autocorrelation peak reaches 0.30, the walk has no measurable rhythm, so return "no rhythm" rather than letting every channel vote, and let the cadence-scaled features use their unscaled fallback (or whatever the bank does for a missing step rate; tell me which).
   - The bug's mechanism (a doubled band-edge estimate) decides 5 of the 13 fallback walks, so it is present, just rarer than feared.
   - Report fix F's paired effect alone and together with fix L, then adopt it.

**The reference for Part 2** is engine v2 with fix L and fix F applied: the "v3 reference". Score it first on the 180 natural walks (both folds, causal, paired against engine v2), and use it as the baseline for everything in Part 2.

## Part 2: DANN, one seed first

**Why.** Every cheap lever moved the result by less than the noise floor, while the gap between same-day and cross-day is 20 to 33 points. DANN targets exactly that gap (Ganin et al., `1505.07818`, in the project files).

**What to build.** Add a gradient-reversal domain head to the CNN-v2 training in `ide_train`, for both the 3-link network and the 1-link (per-link) networks.

- **Where it attaches:** the pooled 896 features (32 channels × 28 frequencies, after the mean over time, before the direction flag is appended).
- **The domain head:** 896 → 64 → ReLU → number of domains, behind a gradient-reversal layer.
- **Domains:** each training session, with the Room B sessions split by layout, because those are the real distribution shifts. For `loso_B2_x` that is A1, A2, A3, B1 identification layout and B1 tracking layout: 5 domains. For `loso_B1_x` it is the same with B2.
- **λ schedule:** the paper's, λ(p) = λ_max × (2 / (1 + exp(−10p)) − 1), with p the training progress from 0 to 1.
- **λ_max:** two values only, 0.1 and 1.0. Small datasets can lose identity under strong alignment, which is why the smaller value is there.
- **Everything else is unchanged:** 6,000 steps, Adam, augmentation, class balance, the feature components, the fusion, fix L calibration at test time.

**Two arms, run both, one seed (seed 0), both folds:**

- **Arm A, domain generalisation (deployable).** The domain head sees only the training sessions. Nothing from the test day enters training, so the model still works straight away. This is the arm that could become engine v3.
- **Arm B, unsupervised domain adaptation (information only).** The domain head also sees the test session's windows, unlabelled, as an extra domain. This is classic DANN. It is not deployable under my rules, because it trains on the test day before the test, so report it only as an upper reference for what alignment could buy.

**How to judge it, controlling seed noise:**

- Train a **same-seed baseline**: the CNNs exactly as in the engine (no domain head), seed 0, fix L calibration.
- Compare each DANN arm against that same-seed baseline, so the seed is held constant. Report the paired change with the participant-bootstrap interval.
- Also report the ensemble with the DANN CNNs swapped in for seed 0's CNN components, against the v3 reference.
- For every arm and λ_max, report:
  - natural accuracy and the paired change [95 %];
  - to B1 and to B2;
  - the walks named PA1;
  - PA2 (of 30);
  - each CNN component alone (accuracy, walks named PA1);
  - the domain classifier's accuracy at the end of training (near chance means the features stopped carrying the session).
- **PROMISING** means all of:
  - Arm A beats the same-seed baseline by at least +4.45 points;
  - it is positive on both folds;
  - it does not raise the number of walks named PA1.
  
  If Arm A is PROMISING, run seeds 1 and 2 and report the three-seed ensemble against the v3 reference. If it is not, stop.
