## 0. The goal

Uzayr wants to know whether the pipeline is correct, and whether anything in it is holding the identification figure down. There are two kinds of item.

**Bugs** (the code does not do what the architecture document says, or does something physically wrong):
- A confirmed bug is fixed and adopted **whatever it does to the figure**, even if the figure drops.
- Report it plainly.

**Candidates** (the code is correct, but a different, literature-backed choice may work better):
- Each is tested against the current best configuration and **adopted only by the rule in §3**.
- Every candidate is reported, adopted or not.

**The baseline is the current headline:**
- the frozen eight-component ensemble;
- trained on TR-AB (Room A plus the other Room B day);
- calibrated with CAL-others;
- scored on natural identification walks, both directions, pooled over the "to B2" and "to B1" folds;

## 3. How candidates are judged

**Test in the fixed stacking order of §7 to §11.** Each candidate is compared with the current best configuration, which includes any fixes and candidates adopted before it. Use the same passes, both folds, and a paired difference with a 95 % bootstrap over participants (10,000 resamples).

**Adopt a candidate only if both hold:**
1. the paired gain on natural walks has a 95 % interval **entirely above zero**;
2. it loses no more than 3 points (point estimate) on slow walks or on fast walks, so natural-pace accuracy is not bought by giving up robustness to pace.

**Report for every candidate:**
- natural, away, towards, slow and fast;
- the paired difference and its interval;
- the decision.

**Bugs are adopted without this rule.** After a bug fix, the fixed configuration becomes the new baseline, and its figure is reported beside the old one.

## 4. Stage 1: capture and packet audit (bug check, no training, minutes)

For every recording and receiver used in the bank:

1. **Packet types.**
   - Tabulate `sig_mode`, `rate`, `mcs`, `bandwidth`, `channel`, `secondary_channel`, `stbc`, `sig_len` and the payload length.
   - Check whether the second half of the payload (the HT-LTF entries) is ever all-zero or otherwise invalid.
   - Any frame of a different type from the recording's majority, or with an invalid HT-LTF half, is a suspect frame.
   - Report their count per pass.
2. **RSSI.** Plot the RSSI distribution per receiver per recording. Flag frames far outside it (foreign transmitters).
3. **Gaps.**
   - Take the inter-packet gaps from the corrected clock, per pass.
   - Report the fraction of passes with any gap over 20 ms, and over 50 ms, and the longest gap.
4. **Gain steps.**
   - Count packet-to-packet jumps in the mean amplitude across subcarriers larger than a threshold fixed in `PLAN.md`.
   - Report how many coincide with an RSSI change, per pass, on each link.
5. **Subcarrier map.**
   - Check the kept indices against the ESP-IDF CSI layout: 64 LLTF entries then 64 HT-LTF entries, each ordered 0 to 31 then -32 to -1.
   - List any kept index that is a null, and any dropped index that is a valid subcarrier.
   - State the true count as unique subcarriers × 2 fields.
6. **The measured packet rate** per receiver, and hence the true frequency ceiling (half the rate).

**Decision.**
- **If suspect frames or foreign packets reach the passes:** this is a bug.
  - Add a frame filter in identification code (never in `pipeline/io/`).
  - Rebuild the bank into `runs/identify/audit/bank_v2/`.
  - Retrain the baseline (TR-AB, both folds).
  - Adopt the fix.
- **Gaps and gain steps:** report only, unless a fix is obvious. If so, it becomes a candidate in §11.
- **Subcarrier map:** report only. Two dropped valid subcarriers are not worth a rebuild.

## 5. Stage 2: a synthetic walker through steps 1 to 4 (correctness, no training)

Write `pipeline/identify/idz_synth.py`. It simulates the receiver's CSI for a walker on line A seen by RX2 beside the TX, and runs it through the real code path:
- `raw_access` amplitude;
- the clock map;
- pass cutting and resampling;
- `id19_featbank.pass_features`;
- `idv2_core.conditioned_map`.

**The simulation:**
- **Paths:**
  - one static path;
  - a torso path whose length changes at 2 F v(t), with F = 0.98;
  - two limb paths moving at 1.5 to 3.5 times v, modulated at the stride rate.
- **Walker motion:** v(t) starts from standstill, reaches 1.2 m/s within about 1 s, and oscillates by ±15 % at the step rate (1.8 steps per second).
- **Per-subcarrier phase:** a path-length-dependent phase on each subcarrier.
- **Output format:** amplitude equals |sum|, quantised to int8 and written into both payload halves.
- **Timestamps:** taken from a real recording, including its gaps.

**Checks.** Write them into `PLAN.md` first, then add them as tests under `tests/`:
1. **Torso frequency.** The recovered torso contour sits within one FFT bin of 2 F v / lambda.
2. **Cadence.** Resolved cadence is within 5 % of the true step rate.
3. **Feature completeness.** On a clean periodic walk, no feature in the 633-column set is NaN.
4. **Gain invariance.** Multiplying all amplitudes by 2 leaves every feature and map unchanged, to numerical tolerance.
5. **Suspect frames.** Inserting 2 % suspect frames (an all-zero HT-LTF half) changes the map's 35 to 70 Hz energy by the amount the stage 1 audit would need to worry about. Report the size.
6. **Edge transients.** Compare the gait-band signal filtered within the pass against the same signal filtered on a continuous stream. Report the error by pass position (first second, middle, last second).

**Decision.** Any failed check is a bug. Trace it, fix it, and adopt the fix as in §3. Checks 5 and 6 are measurements, not pass or fail; they size the effects tested in §4 and §9.

## 6. Stage 3: fusion (candidate, no retraining, minutes)

Use the saved per-component log-probabilities from the identification-walks run (TR-AB, both folds) and from the dev batch's `all_*.npz`.

**Diagnostics first:**
- per component, the fraction of (pass, person) entries at the 1e-9 floor;
- how often the ensemble's decision equals each component's decision;
- the number of passes where one component's floored entry changed the ensemble's decision (a veto): the decision with that component excluded differs, and the true person was chosen without it.

**Variants.** Define them in `PLAN.md` before computing:
- **F0:** current. Floor 1e-9, sum of log-probabilities.
- **F1 (the principled candidate):**
  - tree components (both random forests and the extra trees, 300 trees each) smoothed to (p × 300 + 1) / 306, as one extra vote per person;
  - LDA and the CNNs floored at 1e-3;
  - renormalised, then summed.
- **F2:** every component floored at 1e-2, renormalised, summed.
- **F3:** the arithmetic mean of probabilities instead of the sum of log-probabilities.

**Decision.** F1 is judged by §3. F2 and F3 are reported for information and can be adopted only if F1 is not, and then by the same rule. Also report, for the live brief, the geometric mean (sum divided by 8) as the displayed confidence. It never changes the decision.

## 8. Stage 5: cadence (diagnostic, then candidate)

**Diagnostic, no training.** The identification-walks report said stride rhythm is visible in 3 % of walks, measured on RX2's torso contour. A 0.21 s STFT window cannot resolve the within-step speed change, so test the claim on signals that can show it:
- RX2's Doppler-band energy envelope: summed 10 to 70 Hz spectrogram power per frame;
- the gait-band mean channel.

For natural identification walks, report the fraction with an autocorrelation peak of at least 0.30 in the step range (0.4 to 0.7 s) and in the stride range (0.8 to 1.4 s).

Also report:
- how often the existing cadence resolver's answer agrees with the envelope's;
- per pass, the fraction of the cadence-dependent features (`cad`, `rhy`, `tplacf`) that are NaN and imputed.

**Candidate C1** (feature components only; the CNNs are unchanged).
- **Gate:** run it only if the envelope shows clear rhythm in at least half of the natural walks while the current resolver disagrees or fails on many of them.
- **Change:** add the energy envelope as an input to the cadence resolver, as a new feature version.
- **Retrain:** the five feature components, both folds (minutes).
- **Decision:** judged by §3.

**Always:** write the corrected rhythm-visibility statement for the thesis, whatever C1 does.

## 9. Stage 6: filtering the continuous stream (candidate, bank rebuild)

**Problem.** Today each pass (about 4.3 s) is filtered on its own. The 0.8 Hz and 0.3 Hz band edges need more settling time than `sosfiltfilt`'s default padding (about 0.18 s) gives, so the first and last second of every pass is filter transient. §5 check 6 sizes this.

**Candidate CF.**
- Resample each pass with **3 s of context before and after** it, clipped to the recording limits.
- Apply every band-pass filter to that longer stream, then cut back to the pass (start press to end press) before the per-pass PCA, features and STFT.
- The 3 s after the pass stays within the live 5 s wait, so live operation is unaffected.

**Procedure.**
1. Rebuild the bank (features and maps) into `runs/identify/audit/bank_cf/`.
2. Retrain the current best configuration, both folds.
3. Score it.

**Decision.** Judged by §3.

## 10. Stage 7: frame normalisation of the Doppler maps (candidate, CNN retrain)

**Problem.** The map is dominated by the part of the walk nearest the TX and RX2. The 10 to 35 Hz energy runs 1.79, 0.68, 0.46 by thirds walking away.

**Candidate FN.**

**Decision.** Judged by §3.
