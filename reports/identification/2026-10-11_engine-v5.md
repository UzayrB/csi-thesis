## 1. What engine v5 is

| part | v5 |
|---|---|
| CNN components | each v5 model's three CNN components are its v4 model's files, copied unchanged and sha256-checked (cnn3 and cnn_link0 to 2, seeds 0 to 2, their norms) |
| feature components | six: v4's five and `hgb_pace_prior` (HistGradientBoostingClassifier, random_state 0, on `rf_pace_prior`'s Prior-standardised matrix with pace, sharing its state) |
| training rows | the model's own rows plus extra windows of those rows only: an offset window every 0.05 s from 0.05 to 0.50 s after the press, and time-stretched windows (0.9 and 1.1, pace v / s); no mixup, no M2, no P1 or P2 |
| pace column | the Wi-Fi speed at the model's alpha (loso_B1 0.2, the rest 0.5) |
| run time | three windows per press, at 0, 0.15 and 0.30 s after it, each extracted by the engine's own `Extractor` (an offset window is never cut by the next press), each classified against the same CAL-causal pool; only the 0 s window joins the pool |
| combination | per window s_k = a x (the six feature components' sum) + (the three CNN components' sum), normalised; the three averaged and normalised; the argmax decides |
| the weight a | 0.25 on a tracking walk (layout home) in Room A when the model's training sessions include a Room A session; 1 everywhere else (Room B, a room the model never trained in, every identification walk) |
| confidence | softmax(mean over windows of the raw s_k / A), A = 6a + 3; `ensemble_nopace` without the four pace components |
| decision time | after the 0.30 s window is decided (its window ends at t0 + 4.30 s; t0 + 5.30 s at the latest) |
| the adaptation (the live app, option (c)) | each walk joins the pool and the AdaBN copies are recomputed after its decision is written and shown, at the app's next poll (`identify_engine.AfterDecision`); a later walk is never classified before it, so every decision sees exactly the pool it saw before; the harness (`engine.py`) is unchanged |
| device | the rig runs a v5 model on the GPU (`--device mps`) by default; `--device cpu` stays available (not real time, section 4.2); a v4 model keeps cpu |
| the switch | a model's manifest `engine_version` (5) turns v5 on; any other model runs exactly as v4 |
| the room setting | set once per installation before any press (`rig --room A|B|new`), never from a walk; the manifest gives the rooms the model trained in (deploy_all5_v5: A, B) |
