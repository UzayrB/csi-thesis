## 1. A correction to the brief's definition of A0, made before any number exists

**Corrected 01:36 after reading `id4_verification.py:34`. The first draft of this section named
`spectral_symmetry` as the contaminant. That was wrong and is struck: `spectral_symmetry` is
produced by `pass_features` but consumed ONLY by the phase-D ladder, and it never reaches the
fusion arms this A0 derives from. The real contamination is narrower and worse.**

The brief defines A0 as the reproduced 19b reference **with `speed` and `step_length` removed**.
The 19b reference arm is the per-line standardised embedding fused with
`BEST_D = ["speed", "cadence", "step_length"]` (`pipeline/identify/id4_verification.py:34`).

**Removing `speed` and `step_length` therefore leaves exactly ONE gait feature: `cadence`.** And
that cadence is not clean:

- `speed` = `pass_row["speed_m_s"]`, which `id1_foundations.py:57` sets to the **protocol line
  length divided by the anchor-derived pass duration**. ORACLE on both counts, and PACE.
- `step_length` = `speed / cadence` exactly. ORACLE, PACE, derived.
- **`cadence` is oracle-conditioned.** In `features.py:117-121` the cadence handed to the
  classifier is **doubled** whenever `speed / cadence` exceeds the plausible stride range and
  `speed / (2 * cadence)` falls back inside it. The correction is real gait physics, the
  step-versus-stride harmonic, but **the test that decides when to apply it divides ORACLE speed by
  cadence**. On the 18 September record that test fires on **115 of 360 passes**, so about a third
  of the cadences in the reference arm were resolved using a number a deployed system cannot have.

**So the brief's A0 is not merely contaminated at the edges: its single surviving gait feature is
oracle-conditioned on a third of the passes.**

**Pre-registered consequence.** A0 is defined as the reproduced 19b reference with **`speed` and
`step_length` removed AND `cadence` recomputed by the `id13` three-estimator harmonic resolution,
which uses no speed of any kind.** The brief's version, which keeps the oracle-resolved cadence, is
also reported as **A0-brief, ORACLE-CONTAMINATED**. R3 is judged against A0, not A0-brief.

The difference between the two is itself a measurement worth having: it says how much of the frozen
identification result rests on a harmonic that was resolved with the answer in hand.

**`id11` must confirm all three readings above against the code and report the exact count of
passes on which the doubling fires, per session and per pairing.** If any reading is wrong, the
addendum records the correction before A0 is computed.

## 2. What is fixed before any number exists

### 2.1 Splits, fitting and selection

- Split by **whole session** before any preprocessing. No pass is split across train and test.
- Every fitted statistic comes from the **training sessions only**: standardisation, cross-recording
  PCA, per-line statistics, speed regression, calibration temperature, class priors, enrolment
  templates. Two declared exceptions, labelled at every appearance:
  - **(a) per-recording, label-free** operations fitted inside one recording (subcarrier PCA per
    recording);
  - **(b) transductive arms** in `id16` and `id17` (session alignment, CORAL, AdaBN), always
    separate rows, never merged into non-transductive results.
- **Conditioning parameters** may be chosen by the identity-blind metrics M1, M3, M4 and M5 on any
  session, because no identity label enters them. Anything using identity labels is fixed a priori
  or fitted inside that pairing's training sessions.
- **The test session is never used for any selection**: line, conditioning stage, feature set, head,
  hyperparameter, epoch or seed.
- **No feature ladder grown by looking at accuracy.** Feature groups are the fixed sets in 2.4.
- **Within-day figures may be shown and never support a claim**, because one recording per
  participant-session confounds recording and identity.

### 2.2 The nine cross-day pairings

Single-session training (6): 01 to 02, 01 to 03, 02 to 01, 02 to 03, 03 to 01, 03 to 02.
Two-session training (3): 01+02 to 03, 01+03 to 02, 02+03 to 01.

The two families are reported separately and never pooled. **01+02 to 03 is the canonical pairing**
for comparison with earlier freezes. `id11` confirms this matches `id7` to `id10`, and if it does
not, says so and uses this list.

### 2.3 Heads, fixed now

- **Primary: shrinkage LDA, Ledoit-Wolf, `solver='lsqr'`, `shrinkage='auto'`.**
- Secondary, shown alongside and **never chosen by test accuracy**: L2 logistic regression with
  C = 1, and a linear SVM with C = 1.
- The frozen `score()` picks the better of two heads **by test accuracy**. It is replaced wherever
  reused code calls it, and `id11` records every call site it replaced.

### 2.4 Feature groups per arm, fixed now

| arm | features | label |
|---|---|---|
| A0 | reproduced 19b reference, minus `speed`, `step_length`, `spectral_symmetry`; CSI-only cadence | the bar for R3 |
| A0-brief | the brief's version, minus `speed` and `step_length` only | **ORACLE-CONTAMINATED**, reported for comparison only |
| A1 | ENV: cadence (three estimators reconciled), step-to-step symmetry, cadence variability, band ratio | gait |
| A2 | SPEC: gait cycle time, leg-to-torso rate ratio, stride-normalised leg-contour shape, left-right symmetry, cycle-to-cycle variability, contour periodicity strength | gait |
| A3 | ENV + SPEC | gait |
| A4 | TEMPLATE: nearest enrolment template, DTW with a Sakoe-Chiba band of **10 percent of the cycle length, fixed now**, on stride-normalised contour cycles, voting over the cycles in a pass | gait, classical matching |
| A5 | GAITPAR + A3 | **GAIT+PACE, declared.** R7 applies |
| A6 | tracking-encoder embedding, PCA to 16 dimensions fitted on the training side, per-line z | **NON-GAIT REFERENCE** |
| S0 | oracle keypress speed only | **CONTROL, never shipped** |
| S1 | CSI-sensed torso speed only, runs only if validated | **CONTROL, never shipped** |

Every SPEC identification feature is speed-normalised per section 3.3. No arm other than A5 and S1
contains any speed quantity, oracle or sensed.

### 2.5 Seeds, intervals and reporting

- **5 seeds** (0, 1, 2, 3, 4) for every stochastic arm; report mean and spread across seeds.
- **Primary interval: cluster bootstrap over recordings** (participant-session), 1000 resamples.
  With six recordings per test session this interval is coarse, and every table says so.
- **Secondary interval: pass-level bootstrap**, shown alongside.
- Per-pairing values first, then median, mean and min-max within each family.
- Paired deltas across pairings for every comparison.
- Within-day and cross-day are never pooled.

## 3. The conditioning chain, the metrics and the STFT rule

### 3.1 Stages, in this order

| stage | operation | switchable |
|---|---|---|
| C0 | parse to absolute amplitude, raw | baseline |
| C1 | timestamp-based resampling onto a uniform grid at the nominal rate. Gaps longer than the recorded gap rule are **marked, not interpolated across** | yes |
| C2 | Hampel outlier removal, existing parameters | yes |
| C3 | AGC handling: detect step discontinuities shared by all subcarriers at one instant and report their rate per session; candidate fix is per-packet normalisation by the mean amplitude across retained subcarriers. It also removes genuine broadband shadowing, so it is evaluated separately on band (a) and band (b) by M1 and M4, and kept only where it helps | yes |
| C4 | notch at 50.5 Hz plus any other stationary line found in the empty-room spectra; every notch listed with its evidence | yes |
| C5 | static-path removal: per-subcarrier running-mean subtraction against SVD first-component removal, chosen by M1 | yes, and a choice |
| C6 | subcarrier selection (drop null, guard, pilot, dead), then PCA across subcarriers **fitted per recording** (declared exception (a)). Test discarding PC1 against retaining it, and the number retained | yes, and a choice |
| C7 | split into band (a) 0.8 to 3.5 Hz, the current envelope band, and band (b) about 4 Hz to just below Nyquist, the path-rate band, with notches applied | the split itself is not ablated |

The chain applies to the identification branch only. It never touches the common cleaner, the
tracking transform, or `pipeline/clean/common.py`.

### 3.2 Metrics, per link, cumulative (C0, C0-C1, ... full chain) and leave-one-stage-out, each with a recording-level bootstrap interval

- **M1** walking-versus-standing periodicity AUC: normalised autocorrelation peak in the step-period
  range, walking passes against static dwells, with the empty room as a second null.
- **M2** cross-day cadence Fisher ratio: between-participant variance over within-participant
  across-day variance. Computed inside the training sessions for any decision, on all three for
  description only.
- **M3** cadence estimator agreement: fraction of passes where the three `id13` estimators agree
  within 0.1 Hz.
- **M4** gait-band SNR: gait-band power over adjacent-band power, per link.
- **M5** contour periodicity: autocorrelation peak of the band-(b) torso contour at the gait-cycle
  lag. Identity-blind, and it picks the STFT window.

### 3.3 STFT and speed normalisation

- Hann window, **N in {16, 32, 64} samples** at the resampled rate, which at 150 Hz is 0.107, 0.213
  and 0.427 s, with **75 percent overlap**. Frequency resolution is fs/N, time resolution N/fs.
- **N is chosen by M5 on the training sessions of each pairing, never by identity.**
- Energy-percentile contours: the frequency below which a fixed share of each frame's energy lies.
  The **50 percent contour is the torso proxy** and the **95 percent contour is the leg proxy**.
  Conversion to path rate, and via F to body speed, is **for figures and validation only**.
- Gait cycle from the autocorrelation of the torso contour, first dominant peak at a lag of at least
  0.3 s.
- **Speed normalisation, permitted under the speed policy:** divide the leg contour by that pass's
  own median torso rate (GaitID-style torso-speed compensation), then resample each gait cycle to a
  fixed **32 phase points** (stride normalisation), then average over the cycles in the pass.

### 3.4 Band (b) physical sanity check

For each link and line, predict the torso band from F and a torso speed of 1.0 to 1.6 m/s, and the
leg band from peak swing speeds of two to three times torso speed, using f = 2 F v / lambda with
lambda from the configured channel. Compare with the observed contours. **If the observed energy
does not move with F across links and lines, the spectrogram is not measuring body motion on this
rig and the report says so in those words.** Also report the fraction of band-(b) energy within
10 Hz of Nyquist, as an aliasing warning.

### 3.5 The falsifiable prediction, registered now

The 50.5 Hz line appeared mid-morning on day 2 and sits inside band (b). **Prediction: without C4,
session 02 carries a day-specific artefact and cross-day accuracy on the pairings involving session
02 falls, relative to the pairings that do not involve it.** Tested in `id14`. This is the sharpest
direct test of whether conditioning matters for identification, and it is registered before the
chain is built.

## 4. The speed policy, binding on every stage

- **Forbidden as the identity signal.** Oracle keypress speed, `step_length` derived from it, any
  speed computed from sensed walk duration, and (per section 1) `spectral_symmetry`. None enters a
  gait arm.
- **Allowed as a normaliser.** A pass's own CSI-sensed torso path rate, to normalise its leg
  contour; and stride normalisation to a fixed phase length.
- **Allowed as one declared gait parameter**, in A5 only, under R7.
- **Allowed as a control.** S0 and S1.
- **Allowed as a diagnostic nuisance variable**, regressed out in the R6 diagnostics, which are
  never system results.

**GAITPAR validation gate, fixed now:** CSI-sensed torso speed (torso contour, to path rate, divided
by 2F) against anchor-timed pass speed on the **training sessions**, using the anchors for
validation only. **Threshold: Pearson r >= 0.5.** Four earlier CSI speed proxies correlated below
0.04 with true speed. **If this one misses the threshold, A5 and S1 do not run, and that failure is
itself reported as a finding about what the spectrogram measures.**

## 5. The corridor: selection metric and tie-break, fixed before any corridor number exists

**Candidates.** Every directed line with at least 2 passes per person per session; and every
physical line with both directions pooled, using either direction-invariant features only or
direction as an explicit flag.

**Selection is identity-blind.** Rank candidates by **mean projected bistatic factor F across all
three links**, where F = |(u_TX + u_RX) . v_hat| / 2, then by M1, M3, M4 and M5. **Penalty: any line
on which any link spends more than 25 percent of its length at F < 0.3 is struck out**, not merely
demoted.

**Tie-break, in this order, fixed now:** (1) higher minimum-over-links mean F; (2) higher M5 contour
periodicity on the training sessions; (3) more passes available per person per session;
(4) alphabetical by line name. A tie broken at step 4 is reported as a tie-break and never as a
finding, which is the `id10` lesson.

**Selecting the corridor by identification accuracy is forbidden.** The choice is written into a
timestamped addendum **before any identification number is computed on that corridor**.

**Direction.** The corridor has one designated forward direction, because the same person produces a
different pattern in each direction (Gate-ID mirror patterns).

**R5 stands whatever the outcome: the corridor result on existing data is a PILOT and supports no
claim on its own.**

## 6. Learned models, fixed now

**id17a, prototypical MLP on A3 features.** Linear(d, 32), ReLU, Linear(32, 16). At d = 100 that is
about 3.8k parameters, under the 5k cap. Prototypical loss, class prototypes from the training
sessions, a pass classified by its nearest prototype. Adam, lr 1e-3, batch 64, **200 epochs, final
epoch, no early stopping and no checkpoint selection**. 5 seeds.

**id17b, 2D CNN on conditioned spectrograms.** Per-link band-(b) spectrograms, plus one variant with
band (a) stacked in. Conv(1->8, 3x3)-BN-ReLU-MaxPool2, Conv(8->16, 3x3)-BN-ReLU-MaxPool2,
Conv(16->32, 3x3)-BN-ReLU, global mean pool, Linear(32, 6). About 6.1k parameters, under the 50k
cap, justified against n = 360 passes. **Weights shared across links, mean pooling over links.** Two
heads under the same budget: cross-entropy, and prototypical with nearest-prototype inference. Adam,
lr 1e-3, batch 32, **100 epochs, final epoch, no early stopping**. 5 seeds.

**Fixed-size crop, registered now:** centre crop on the time axis to the number of frames implied by
the **10th percentile of pass duration**. Passes shorter than that are excluded from `id17b` and the
excluded count is reported. **Time resampling is not used to fit the crop**, because it alters path
rate.

**Augmentation. Allowed:** time shift or crop, amplitude gain jitter of plus or minus 10 percent,
additive Gaussian noise at 20 dB SNR, link dropout at p = 0.2, time masking of up to 10 percent of
frames. **Forbidden:** frequency shift, time stretch, resampling, because they alter cadence and
path rate.

**Controls:** label-shuffle control, and an AdaBN variant on the test session declared transductive.

**Speed leakage:** R6 on the penultimate-layer embedding, and one registered variant of `id17b` with
a **speed-normalised frequency axis**, each spectrogram rescaled by its own median torso-contour
rate. That is a normalisation under the speed policy, not an augmentation.

**DANN is not re-run.** With two source sessions it sits below the source-count regime in which
Ganin and Jiang report adversarial gains, which matches the four earlier nulls here. It becomes a
DC2 question once five sessions exist.

## 7. Decision rules, copied verbatim from the brief

- **R1 SIGNAL-VITAL.** A conditioning stage is signal-vital if removing it from the full chain
  (leave-one-stage-out) worsens M1 or M2, with a recording-level bootstrap interval on the delta
  that excludes zero. Report which metric it moved.
- **R2 TASK-VITAL.** A stage is task-vital if it is signal-vital and its removal also lowers
  cross-day accuracy on at least 5 of 9 pairings, with the paired median delta's interval excluding
  zero.
- **R3 SHIPS.** A new representation or model ships if it beats the reproduced reference A0 on at
  least 5 of 9 pairings, with the paired interval excluding zero.
- **R4 DAY-BIAS SUPPORTED.** Supported only if both hold: the transductive alignment arm raises
  cross-day accuracy by the R3 criterion, and the voting curve rises (the largest k beats k = 1
  outside k = 1's interval). It was previously flat.
- **R5 PILOT.** The corridor result on existing data is a pilot whatever its outcome, and supports
  no claim on its own.
- **R6 GAIT, NOT PACE.** An arm counts as gait identification only if all three hold:
  - its speed-residualised version (DIAGNOSTIC, `id14`) stays above the 95th percentile of the
    permutation null on at least 5 of 9 pairings;
  - the drop caused by residualising is reported with its interval;
  - a linear probe predicting pass speed from its features is reported, with R squared fitted on the
    training side and scored on the test side.

  An arm that fails R6 is reported as encoding pace, however high its accuracy.
- **R7 DECLARED PACE COMPONENT (A5 only).** A5 runs only if CSI-sensed torso speed validates against
  anchor speed at the pre-registered threshold (default: Pearson r >= 0.5 on training sessions). If
  it runs, A5 counts as a gait-parameter result only if:
  - it beats S1 (CSI-sensed speed only) on at least 5 of 9 pairings, with the paired interval
    excluding zero;
  - A5 with its speed columns removed passes R6.

  Otherwise it is reported as pace adding to gait, not as gait.

## 9. The three pre-registered outcomes

- **Outcome 1: a gait arm passes R3 and R6.** Identification ships as gait. The corridor and DC2
  carry it forward, and DC2's pace blocks are the confirming test.
- **Outcome 2: a gait arm passes R6 but not R3.** There is gait identity, but it is weak. The
  defensible claim is small-cohort gait identification, using the two- and three-person subsets, and
  DC2's longer corridor walks decide whether six-way identification becomes viable.
- **Outcome 3: no gait arm passes R6.** On this data the identity signal is dominated by pace and
  session. Report it as a measured sensing limit of three single-antenna, amplitude-only 2.4 GHz
  links, with the evidence chain from this run. Compare qualitatively with Custance et al., noting
  that theirs is a preprint on a different task, and name DC2 as the final test.

No sentence in the closing claim may cite a within-day figure, a speed-containing arm as an
identification result, or the eight-class history.

## 10. Open questions `id11` must answer before the stages that depend on them

Each is recorded here as open, so that the answer cannot later be presented as a prediction.

1. **Does the windowed artefact preserve what band (b) needs?** `common.pass_stream` reads
   `runs/.../windows/room_A/session_XX/<stem>.npz` and reconstructs a continuous stream by taking
   the first 150 samples of each 2 s window at 1 s stride. If per-packet timestamps did not survive
   into that artefact, **C1 cannot be done from it** and either the parse must be re-read read-only
   from `data/`, or C1 is marked NOT POSSIBLE and the consequence for band (b) is stated. This is
   the single largest technical risk in the run.
2. **Actual packet rate, jitter, loss and the longest gaps** per link per session, and therefore the
   true Nyquist frequency against the nominal 75 Hz.
3. **Subcarrier count and identity.** `common.py` carries 107 subcarriers, not 52. Which are null,
   guard, pilot or dead, and what C6 should drop.
4. **The channel number, and therefore lambda.** Band (b) physics is wrong without it.
5. **Is AGC gain logged** in `rx_ctrl` on these ESP32-WROOM-32 boards? Generally it is not, which is
   why C3 uses a gain-invariant normalisation.
6. **Gait cycles per pass.** `gait_windows` includes `walk_edge`, taking a pass from about four
   seconds to about ten, while `id1_foundations` computes duration from `walk` only. Both numbers
   are reported. At the implied 1.66 m/s a 5 m line gives roughly 2.5 cycles on the `walk` span, and
   this sets the DC2 corridor length.
7. **Frequency resolution.** For the median pass duration T, 1/T against the between-participant
   cadence spread. **If between-person cadence differences fall below 1/T, say plainly that FFT-peak
   cadence cannot resolve them.**
8. **Pass counts per participant, session and directed line.** The 48 groups at k = 2 in `id10`
   suggest lines A to D are walked twice per person per day and edge lines once. Confirm or correct.
9. **Do static dwells and empty-room baselines exist per session?** M1 needs both nulls. If either
   is missing, M1 is redefined in the addendum before it is computed.
10. **Cadence sanity.** The 2.34 Hz median implies about 140 steps per minute, which is brisk for
    short indoor lines, and is consistent with residual step-versus-stride harmonic confusion.
    Tested by the three-estimator agreement in `id13`.
11. **Prior code inventory.** Any earlier STFT, WifiU, PCA or SVD implementation, and the data it
    was run on. Reuse what works rather than rebuilding it.
