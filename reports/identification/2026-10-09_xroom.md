## 5. What was run

- **Four models, engine v4's recipe** (`PREREG_XROOM_V4.md` section 1): `xr_AB_v4` (A1, A2, B1; 600 walks),
  `xr_ABtrk_v4` (A1, A2, B1 tracking walks; 360), `xr_A_v4` (A1, A2; 240), `xr_B1_v4` (B1; 360). Five feature components
  on `bank_T4.0_v4`; three CNN components trained on the 3.0 s maps of `bank_T3.0`, which is what every v4 model carries
  (its CNN files are the v1 models' weights, copied unchanged through v2, v3 and v4). `bank_T3.0` was recovered byte for
  byte from git (3f3612b4^). End-detector alpha 0.5 for all four by the PLAN rule (B1's fit for `xr_AB_v4` and
  `xr_B1_v4`; no identification walks for the other two).
- **Config check (no training):** given A1, A2, B1 and B2 the wrapper reproduces `loso_A3_v4`'s 899 training rows and its
  manifest config field for field.
- **Replays:** `ide_replay` (the leave-one-session-out replay path), T 4.0, on mps; tracking walks with the route known,
  identification walks with the direction detected as shipped. CAL-none through the engine's own `Session.classify`
  with an empty pool.
- **Leak proof** (`runs/identify/engine/xroom/audit/`): each training ran under a Python audit hook that logged every file
  opened; the only repository files opened were code, the two banks (training indexed its own rows only), the GS
  decision file and the model's own output. Each model's saved training rows equal the specified rows exactly, with no
  A3 or B2 row. Substitution check: with every non-training row replaced (features and maps by noise; labels, paths and
  sessions shuffled; speeds random), every model's feature components and CNN components (30 steps, CPU) came out
  identical, 9 of 9 for each model.
