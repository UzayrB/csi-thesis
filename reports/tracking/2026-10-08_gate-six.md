## 0. Outcome: the STOP case

**The dwell-free rule moves the threshold** from 0.431 to **0.983** on the scaled statistic the decoder reads.

**Flips that can reach an output:** 4,690 windows inside the decoder's own ranges change from walking to still.
- **Every session and both models are affected:** fin on A1, A2, B1, A3 and B2, and zsf on B2.
- **Flips in the windows the display lock reads:** 18 to 35 passes per session have at least one.

**As the brief says:** nothing is re-decoded, and the choice below is Uzayr's.

**Two further findings bear on the thesis claim "six participants and no static dwells":**
- **No dwell-free still class exists in A1 or A2.** The candidate the brief names first, the idle windows before
  the first press, is not reliably still (section 2). The 0.983 is the threshold that class gives, not a better
  estimate of the boundary between standing and walking.
- **Other gate values touched dwells too.** The null rule (still weight 4.0, offset -7.5, quantile 0.75), the veto
  and the bout prior were selected or fitted on whole A1+A2 recordings, dwell block included. They used six
  participants. Re-deriving the threshold alone would not make "no static dwells" true (section 1).

## 2. The still class (step 2)

**Candidates weighed against "reliably not walking, from the protocol":**
- **Standing between passes: rejected.** Mode B of the capture protocol (`pipeline/io/ground_truth.py`) gives no
  instruction to stand between passes. The participant walks to the next line's start, and 53.2 % of transit windows
  read as walking.
- **Empty-room baselines: rejected.** They are not walking, but they hold nobody, which makes them a different class
  from a standing person. They also separate from walking perfectly (AUROC 1.000 on A1), so a balanced-accuracy
  threshold would sit at the single lowest walking window.
- **Idle windows before the first press: not reliably still.**
  - The A1 and A2 protocol (9 and 10 Sept) gives no stillness instruction before the first walk. The 15 s rule dates
    from 29 Sept.
  - On the scaled statistic, these windows have median 0.794 on A1 and 1.205 on A2. Walking has 2.208 and 1.804.
  - At 0.431, 69.2 % (A1) and 84.7 % (A2) of them already read as walking.

**Conclusion: in A1 and A2, the only protocol-guaranteed still person is the standing sweep, which the brief
excludes.**

**Pre-registered anyway:** the idle windows before the first press.
- **Why this source:**
  - it is the source the brief names first;
  - it is the deployed system's own quiet-period definition;
  - it holds no dwell and no removed participant.
- **Labelled throughout as not reliably still.**

## 5. Flips, old values against new (step 4)

**What a flip is.** G0 and g_rec are unchanged, so the scaled statistic is identical under both settings. A flip is a
window where (s < 0.431) differs from (s < 0.983). **Every flip runs from walking to still.**

**What reaches an output, from the code.** The shipped decode (`night_arms.night_track`; live, `pipeline/live/decoder.py`
calls the same function) reads the gate only on [lo, lo + 40]:
- lo is the window centred on the start press;
- 40 windows = 20 s;
- every read in `night_track` starts at `lo_dec = lo`, because the shipped options have no run-up and the display
  lead-in is 0;
- the gate enters through `decoder2.stack2`: a still window forbids every path state (the veto, hysteresis 1) and
  sets the null's still and transit levels.

**So a flip inside a decode range can reach:**
- the committed line, through the causal exit and the rescore;
- the lock and the drawn track, through the display decode (live: `pipeline/live/display.py`, the same
  `night_track` from lo);
- the one mid-walk switch, through `switching.Scorer`, which stacks the same gate with `stack2` and reads from lo
  onward.

**Windows before the first press cannot reach an output.** They feed only g_rec, the relative RSSI and AdaBN, which
read the raw energy and never the threshold. They all end before the first decode starts. Windows outside every
decode range cannot reach an output either.

**The start-of-walk readers** read the windows that end between 2 s before and 1 s after the press
(`tracking._terms_due`). They use no gate energy.

## 6. Uzayr's decision

**(a) Adopt 0.983.**
- **What it means:** re-decoding A3 and B2 for both models, and new headline figures.
- **What it is built on:** a still class this report finds is not reliably still.
- **What it does not fix:** the null rule, the veto and the bout prior would still carry the dwells. They were
  selected with 0.431, and adopting 0.983 without re-selecting them would pair a new gate with a decoder tuned to the
  old one.

**(b) Keep 0.431 and disclose its origin.**
- **What it means:** nothing changes.
- **The draft sentence for the thesis, for this option only:**

> The motion-gate threshold (0.431 on the scaled band energy) was fixed on 11 September, before the cohort was
> reduced to six. It was placed by balanced accuracy between A1's standing-sweep windows and A1's walking windows from
> all eight participants, and checked on A2. The decoder's null rule, veto and bout prior were then selected on A1
> and A2 (six participants) with the standing-sweep block among their off-path windows. No dwell-free re-derivation
> was possible: in A1 and A2 the only protocol-guaranteed still person is the standing sweep, and the idle period
> before the first press is not reliably still. Every network, reference statistic (G0, g_rec) and test figure uses
> the six participants only.

**Under (b), "no static dwells" cannot stand as written.** The claim would need to read "trained on six participants;
standing-sweep data used only to place the motion gate and select the decoder's null rule on the development
sessions", or the like.

**The outputs-identical sentence the brief anticipated cannot be written.** The outputs are not identical under the
new value.

**Decided (Uzayr, 8 October, about 19:05; recorded 19:10 by the primary chat, the gate chat having closed): (b).**
Keep 0.431 and every other gate and decoder setting. No re-decode and no configuration change; nothing in the
deployed or zero-shot model changes. The draft sentence above is the basis for the thesis disclosure.

**Not tuned with the dwells:** G0 (0.7542, deployed and zero-shot) and each recording's g_rec use only idle windows
that end before the first press (Section 1). Every network was trained on walking windows only.

**What the "veto" is, in plain terms.** When the motion gate reads a window as still (scaled band energy below
0.431), the decoder is not allowed to place the walker on any of the twelve lines in that window. It must put the
person in a standing or between-lines state instead. With hysteresis 1, a single still window is enough to apply
it (`decoder2.stack2`: every line state's score is set to an impossible value in that window). The still weight of
the null rule is the softer partner of the veto: it tilts the standing state up, and the between-lines state down,
by 4.0 for every still window, and the reverse for every walking one.
