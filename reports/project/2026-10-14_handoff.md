## 6. Rules that persist (and the lessons of 10 to 14 October)

**The machine:**
- Every heavy job asks the Mastermind for its slot by message. MACHINE_STATE is written before and after every heavy step
  and read back; QUIET only when nothing heavy runs.
- **Timed runs** (confirmation runs, renders) run alone on the machine, with a LaTeX hold on the Editors (Uzayr's VS Code
  builds `Main.pdf` when he saves a `.tex`, so tell him too). Untimed checks need no hold. Uzayr may waive this; take his
  words in the agent's own chat.
- Limits: training 6 GB (MPS 0.3/0.2); replays 12 GB (MPS 0.7/0.5); killed below 30 % free; nice 10 and
  `OMP_NUM_THREADS=1` (nice 0 for a timing run). A worker pool counts as one job under a total-memory guard.
- **One caffeinate, the Mastermind's,** started detached (`nohup caffeinate -ims -t <seconds> & disown`) with a timeout as
  its fail-safe, released on the agent's DONE. Check with `pgrep -lf caffeinate` and `pmset -g assertions`.
- **Tracking replays must force the CPU.** Calling `app_replay.replay_inner` directly skips the app's `force_cpu()` and runs
  the networks on the GPU, which changes switches and dot figures (14 Oct, section 6.1 of the head-offset record). Use the
  app's own command line, or call `force_cpu()` first, and record the device in every output.
- Stop processes by PID only, never `pkill` broadly. A pause (`kill -STOP`) is reversible and preferred when stopping
  someone else's run at Uzayr's word.

**Evidence:**
- Rules (pass rules, guards, memory rules) are committed before the run they judge. A change after a result is Uzayr's
  call, and is disclosed as such.
- Never accept an exactness difference on your own; stop and report.
- Recompute headline figures from the run's own files before approving a record.
- **Read the clock** (`date`) before writing any time, in records, commits and peer messages alike. Typed times slipped
  into messages several times on 11 to 14 Oct and each needed a correction.

**Files and git:**
- Never edit `data/`, `pipeline/io/`, firmware, `PREREG_*`, existing reports, or hash-listed files without a plan, a
  re-hash and an exact reproduction. New findings go in new files.
- Commit named paths only (`git commit -- <paths>`), check `.git/index.lock` first, push after committing, and end each
  message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never run git in the report repository, and never write into it.
- Python: `/opt/anaconda3/bin/python3` with `OMP_NUM_THREADS=1 PYTHONPATH=.` from the Code root.

**Names:** first names are allowed in Code markdown; the LaTeX report uses only PA1 PA1, PA2 PA2, PA3 PA3,
PA4 PA4, PA5 PA5, PA6 PA6. Some Code reports print the key (for example section 6 of the engine v5 reports); the
Editors keep them on their stay-out list, so never paste a name into a message meant for the report.

**Writing:** British spelling, no em dashes, connected sentences.
